# NebulaTech 星云科技数据库管理制度

## 环境划分

公司数据库分为 Development、Testing 和 Production 三类环境。三个环境使用独立账号和独立网络访问策略，禁止直接复制生产账号权限到开发或测试环境。

## Development 开发数据库

### Development Schema 变更

开发数据库的 Schema 变更不需要审批。具有对应项目开发权限的工程师可以直接执行建表、加列、删除测试表等操作，但必须在项目 Git 仓库中保留可重复执行的迁移脚本。

### 数据限制

开发数据库不得存放未经脱敏的真实客户个人信息、访问令牌或生产 API Key。需要调试真实数据结构时，只能使用经过脱敏的样例数据。

## Testing 测试数据库

### Testing Schema 变更

测试数据库的 Schema 变更必须由发起人的直属 Team Lead 审批。审批记录必须关联迁移脚本的 Git commit；仅有聊天消息不能作为有效审批记录。

### 数据刷新

测试数据库可从生产数据生成脱敏副本。脱敏任务由数据平台服务账号执行，普通工程师不得自行导出生产原始数据到测试环境。

## Production 生产数据库

### 生产数据库变更

生产数据库的 Schema 变更必须由数据库负责人 DBA 和当周值班 SRE 双人审批。两名审批人必须是不同人员。变更单必须包含迁移 SQL、影响表、预计锁表时间和回滚 SQL，缺少任一项不得进入执行阶段。

### 变更窗口

常规生产数据库 Schema 变更只能在每周二或周四 20:00 至 22:00 执行。进入窗口前必须完成测试环境验证，并在变更单中附验证结果。

### 紧急数据库变更

当 P0 或 P1 事故需要立即修改生产数据库时，可使用紧急变更流程。紧急生产数据库变更必须由 DBA 和当次事故的 Incident Commander 双人批准，不要求等待周二或周四窗口，但变更单必须在事故恢复后 4 小时内补齐。

## 数据库权限

### 人员访问

普通研发人员默认没有生产数据库写权限。排障所需的生产数据库临时只读权限由 DBA 审批，单次授权最长 2 小时；临时写权限必须由 DBA 和安全负责人双人审批，单次授权最长 1 小时。

### 应用账号

生产应用账号必须遵循最小权限原则，只允许访问业务运行所需的数据库、表和操作类型。生产应用账号不得被人员用于交互式登录。

## 审计

Production 数据库的登录、授权、DDL 和写操作审计日志保留 180 天。任何人不得删除或关闭生产数据库审计日志。

## 环境隔离与执行边界

三类数据库环境的审批强度不同，是为了让低风险环境保持开发效率，同时让 Production 变更具备独立复核。Development 的“无需审批”只表示不需要人工变更审批，不表示可以绕过代码版本管理；Testing 的 Team Lead 审批用于确认迁移脚本与测试目的；Production 的双人审批用于防止单人误操作直接影响客户业务。

Production Schema 变更与 Production 应用发布属于不同变更对象。数据库变更应遵守本文件的数据库审批人与数据库窗口，应用发布应遵守 `deployment_manual.md` 中的发布流程，不能因为一次应用发布已经获批就自动获得数据库 Schema 变更权限。

生产访问权限也不能通过共享账号转移给其他人员。临时授权绑定申请人与授权目的，排障结束后应停止使用该权限。应用账号面向程序运行，人员临时访问面向排障，两类身份在审计中必须能够区分。

常规变更与紧急变更均应保留可审计的变更单。紧急流程只缩短等待窗口，不取消审批、回滚信息和事故后的记录要求。
