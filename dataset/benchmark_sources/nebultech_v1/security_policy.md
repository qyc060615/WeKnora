# NebulaTech 星云科技信息安全制度

## 密码

### 密码复杂度

公司统一身份系统密码长度不得少于 14 个字符，并且必须同时包含大写字母、小写字母、数字和特殊字符。禁止使用公司名称、员工姓名或连续 4 位及以上数字作为密码的一部分。

### 密码处理

密码不得写入代码仓库、工单正文或团队聊天。只有在检测到泄露、员工主动报告泄露或安全团队要求时才强制重置；公司不要求无事件情况下按固定周期修改密码。

## 多因素认证 MFA

### MFA 适用范围

所有员工登录公司统一身份系统必须启用 MFA。访问 Production 管理控制台、财务系统和安全管理平台时，必须使用硬件安全密钥或公司批准的 Passkey；短信验证码不能作为这些高敏系统的第二因素。

## API Key

### API Key 存储

服务端 API Key 必须存放在公司 Secret Manager 中，禁止写入 Git 仓库、容器镜像、Wiki 或明文配置文件。CI/CD 通过工作负载身份读取 Secret Manager，不得把长期 API Key 复制到流水线变量。

### API Key 生命周期

长期 API Key 的最长有效期为 90 天，到期前必须轮换。发现 API Key 泄露后，持有人必须在 15 分钟内撤销旧 Key，并创建新 Key；仅删除公开代码中的字符串不视为完成处置。

## SSH Key

### SSH Key 要求

新建 SSH Key 必须使用 Ed25519 算法。个人 SSH 公钥最长登记有效期为 365 天，到期后需要重新登记；私钥必须保存在受系统保护的本地密钥存储中，禁止通过聊天或邮件传输。

## 数据访问

### 机密数据

访问标记为 Confidential 的客户数据必须同时获得数据 Owner 和安全负责人的审批。审批有效期最长 30 天，到期自动撤销。批量导出 Confidential 数据还必须记录导出用途和接收方。

### 最小权限

权限申请只能包含完成当前职责所需的最小资源范围。共享账号不得用于访问 Production、财务系统或安全管理平台。

## 安全事件上报

发现凭证泄露、异常登录或未授权数据访问后，员工必须在 15 分钟内通过 `#security-incident` 频道上报，并保留相关日志，不得自行删除证据。

## 凭证边界说明

Password、API Key 和 SSH Key 都属于认证凭证，但用途和生命周期不同。Password 面向人员身份登录；API Key 主要用于服务或 Workspace 集成；SSH Key 用于基于公私钥的主机或代码访问。三种凭证不能因为都能“登录”就使用同一保管方式或同一有效期规则。

MFA 是对人员身份认证的第二层保护，不替代 Password，也不替代服务间 API Key。高敏系统要求的硬件安全密钥或 Passkey 是 MFA 因子，不能把普通短信验证码视为等价方案。员工更换设备时应重新完成受控注册，而不是把旧设备中的密钥材料直接复制到聊天工具。

当凭证疑似泄露时，处置目标是终止泄露凭证的继续使用，而不仅是删除暴露位置。特别是 API Key 已进入公开仓库后，即使提交被删除，也应假设 Key 已被读取并按泄露流程撤销。

Confidential 数据审批针对数据访问本身，不因为员工已经拥有某个系统账号就自动获得访问资格。系统身份和数据授权必须同时满足。
